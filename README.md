# Афиша Башкортостана

Поиск культурных событий по вопросу на русском языке. Можно указать город, день, возраст ребёнка, бюджет на группу, время окончания и предел поездки. В диалоге работают уточнения и продолжения, например «А подешевле?», «А что ещё?» и «А в воскресенье?».

## Запуск

Node.js 24.15+ и Docker Compose. Скопируйте `.env.example` в `.env` при первом запуске и задайте `POSTGRES_PASSWORD`.

```bash
npm ci
docker compose up -d --wait db
npm run migrate:catalog # если есть data/catalog.sqlite
npm start
```

- Веб-приложение работает на [localhost:3000](http://localhost:3000).
- Fastify API работает на [localhost:3001](http://localhost:3001/health).
- `npm start` запускает API и Vite отдельными процессами. Для раздельного запуска используйте `npm run start:api` и `npm run dev:web`.
- `npm run build` собирает веб-приложение в `apps/web/dist`.

```bash
docker compose up -d --wait db
npm run migrate:catalog # если есть data/catalog.sqlite, до запуска api
docker compose up -d --build --wait
docker compose exec api npm run refresh
```

PostgreSQL 18 хранит каталог, аккаунты, сессии, чаты и подписки в томе `postgres`. Миграция переносит данные из SQLite с прежними идентификаторами и оставляет исходный файл на месте. Локальный API автоматически переносит `data/catalog.sqlite` при первом запуске с пустым каталогом. Для нового каталога запустите `npm run refresh`. В Docker пустая база начинает обновляться при первом запуске API. Интервал `REFRESH_INTERVAL_MINUTES` по умолчанию составляет 360 минут в Docker и 0 локально.

## Архитектура

- `apps/web` содержит React и Vite. Поиск открывается на `/`. Каталог, карточки, виджет и API-справка доступны на `/catalog`, `/events/:id`, `/widget` и `/docs`.
- `apps/api` содержит Fastify, PostgreSQL, поиск, импорт, аккаунты и чаты.
- `apps/bot` содержит отдельный TypeScript-процесс grammY. Бот обращается к Fastify по HTTP.
- `packages/contracts` содержит типы и общие категории.

Для Telegram скопируйте `.env.example` в `.env`, задайте `BOT_TOKEN` от BotFather и одинаковый `BOT_API_TOKEN` у бота и API. Перезапустите API и запустите `npm run start:bot`. В Docker используйте `docker compose --profile telegram up --build`. `PUBLIC_SITE_URL` добавляет публичные HTTPS-ссылки на сайт. Подписки хранят идентификатор чата и фильтры до отписки. Рассылка пока не включена.

## Аккаунты и чаты

Войдите через `/login` или зарегистрируйтесь через `/register`. Чаты после входа хранятся в аккаунте. История до входа остаётся в открытой вкладке.

Для входа через Telegram в [BotFather](https://t.me/BotFather) откройте настройки бота → Login Widget. Добавьте адрес сайта и полный адрес возврата `https://ваш-домен/api/v1/auth/telegram/callback`. Укажите адрес сайта в `PUBLIC_SITE_URL`, а выданные BotFather параметры в `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET`, затем перезапустите API. Для локального входа через почту откройте `http://localhost:3000` или задайте свой `PUBLIC_SITE_URL`.

## Как работает подбор

Для поиска через Timeweb AI Gateway задайте `TIMEWEB_API_KEY` и `BASE_URL=https://api.timeweb.ai/v1` в `.env`. Модель `openai/gpt-6-luna` извлекает условия запроса и ранжирует до 25 событий, прошедших проверку обязательных фильтров. Если пользователь ещё выбирает, модель может предложить варианты и задать один вопрос о жанре или интересах. Сведения о ценах, времени и возрастных ограничениях берутся из каталога. При отказе модели работает локальный поиск. Для другого OpenAI-совместимого провайдера задайте `DISCOVERY_MODEL`, `DISCOVERY_MODEL_KEY` и `DISCOVERY_MODEL_BASE`.

Для голосового поиска нажмите кнопку микрофона на сайте и произнесите вопрос. Текст появится в поле ввода во время записи и уточнится после остановки. Проверьте его и отправьте вопрос. Микрофон требует разрешения браузера и доступен на localhost или HTTPS. Во время записи сервер периодически отправляет накопленное аудио в Timeweb AI Gateway, поэтому текст обновляется с задержкой. Если задан `OPENAI_API_KEY`, сервер использует OpenAI Whisper (`whisper-1`).

Бюджет на группу считается по опубликованной начальной цене билета. Доступность билетов проверяйте у источника. Если данных для фильтров не хватает и подтверждённых совпадений нет, ответ показывает, сколько проверенных событий содержат все нужные сведения. Для оценки поездки на машине задайте `ROUTING_ORIGIN` с адресом сервера OSRM. Пользователь указывает точку отправления координатами или названием площадки с координатами в каталоге. Сервис показывает оценку поездки без учёта пробок.

`npm run refresh` печатает JSON-отчёт по каждому источнику сразу после сохранения записей. Отчёт содержит длительность, количество принятых и отклонённых записей, изменения и ошибки источника. Сборщики ограничивают параллельность и размер ответа, учитывают robots.txt для обхода страниц и прекращают новые запросы к сайту после HTTP 429. Сбой сохраняет ранее загруженные данные. Отсутствие карточки в ограниченной выборке само по себе не подтверждает отмену. Время последней проверки видно в карточке.

Региональные афиши, опубликованные только изображением, требуют дополнительной проверки. Такие объявления и диапазоны без точного времени посещения пока не превращаются в карточки. Данные организаторов не получены. Модерация, планировщик дня и формальная оценка уровня хакатона остаются отдельными задачами.

Переданный аналитиком набор содержит вымышленные события. Он доступен только в [изолированном тестовом каталоге](test/fixtures/analytics/README.md). [Контрольные запросы](test/evaluation/README.md) проверяют поиск на этом наборе без обращения к модели.

После `npm run refresh` и запуска API команда `node scripts/test-live-search.mjs 3` повторяет проверки по официальным расписаниям ноября 2026 года. Проверки рассчитаны на период, пока соответствующие сеансы есть в выдаче. Они отправляют обычные запросы к API, включая обращения к модели, если она настроена.

## Postman

Сначала запустите приложение по инструкции выше.

Для проверки аккаунта используйте один хост `http://localhost:3000`, чтобы Postman сохранял cookie `afisha_session`. Для `POST` добавьте `Origin: http://localhost:3000` и `Content-Type: application/json`. Токен API не нужен.

| Запрос | Тело и результат |
|---|---|
| `POST http://localhost:3000/api/v1/auth/register` | `{"name":"Лена","email":"lena@example.test","password":"long-example-password"}`. `201` и cookie сессии. |
| `POST http://localhost:3000/api/v1/chats` | `{}`. `201` и `chat.id`. |
| `POST http://localhost:3000/api/v1/chats/{id}/turns` | `{"message":"Посоветуйте кино в Уфе","requestId":"postman-1"}`. `200` с сохранённым запросом и ответом. |
| `GET http://localhost:3000/api/v1/chats/{id}` | `200` с историей при наличии cookie. Без cookie вернётся `401`, а аккаунту, которому чат не принадлежит, вернётся `404`. |
| `POST http://localhost:3000/api/v1/auth/logout` | `{}`. `204`. Последующий запрос истории с отозванной cookie вернёт `401`. Запись с чужим `Origin` вернёт `403`. |

| Метод и URL | Заголовки и тело | Ожидаемый ответ |
|---|---|---|
| `POST http://localhost:3001/api/v1/discover` | `Content-Type: application/json`, `{"message":"Куда сходить в Уфе в эти выходные?"}` | `200`, поля `status`, `message`, `constraints`, `events`, `suggestions`, `context`. Состав выдачи зависит от даты и базы. |
| `POST http://localhost:3001/api/v1/discover` | Тот же заголовок, `{"message":"А подешевле?","context":{...}}`, где объект `context` взят из первого ответа | `200`. Город и даты сохраняются. Порог цены привязан к предыдущей подборке. |
| `POST http://localhost:3001/api/v1/discover` | Тот же заголовок, `{"message":""}` | `400`, `invalid_message`. |
| `POST http://localhost:3001/api/v1/transcribe` | `Content-Type: audio/wav`, Body → binary → файл WAV с русской речью до 1 МиБ. Токен в Postman не нужен. | `200`, `{"text":"Куда сходить в Уфе?"}` для соответствующей записи. Для `text/plain` вернётся `415`, для пустого аудио — `400`. |
| `GET http://localhost:3001/api/v1/events?limit=5` | Без токена и тела | `200`, список событий и параметры страницы. |
| `PUT http://localhost:3001/api/v1/bot/subscriptions` | `Authorization: Bearer <BOT_API_TOKEN>`, `Content-Type: application/json`, `{"subscriber":"1","city":"Уфа","category":"concert"}` | `200`, `{"saved":true}`. При настроенном токене без авторизации возвращается `401`. |
| `DELETE http://localhost:3001/api/v1/bot/subscriptions` | Те же заголовки, `{"subscriber":"1"}` | `200`, `{"removed":1}` после PUT, затем `{"removed":0}`. |

Административный импорт требует `ADMIN_TOKEN`. Отправьте массив JSON на `POST http://localhost:3001/api/v1/admin/import` с заголовками `Authorization: Bearer <ADMIN_TOKEN>` и `Content-Type: application/json`. Записи содержат `title`, `category`, `startsAt` с часовым поясом, `city`, `venue`, `sourceName`, `sourceUrl`, `status` и по возможности стабильный `sourceKey`. Для CSV используйте те же колонки и `Content-Type: text/csv`. Ответ `200` содержит счётчики импорта и причины отклонений. Повтор записи увеличивает `unchanged`.

`npm test` запускает проверки API, каталога, импорта и Telegram на контролируемых данных. `npm run typecheck` проверяет все рабочие области.
